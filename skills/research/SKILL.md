# Research

## Bound the question

Establish the question, source/project boundaries, period and deliverable from the request and settled context. Consult connected project sources before asking for information they may contain. Ask only about material gaps; continue independent authorized work. Stop when the question is sufficiently supported or, after considering relevant available alternatives, an evidence/access limit prevents an answer. Report partial coverage without endless searching or arbitrary source quotas.

## Inspect the owning sources

Use **primary sources**: official documentation, source code, specifications and first-party APIs. Trace factual claims to their owning source. Secondary write-ups, snippets, unopened links and worker summaries are leads, not verified evidence. Reuse relevant inspected evidence.

Check relevant dates, versions, environment and revision; verify changeable facts against their current owner. For code/API questions, distinguish declared, locked and installed versions and record the inspected commit/local content basis. Use matching official documentation or installed/release-tagged source. Report material mismatches/access gaps and refresh invalidated evidence.

## Assess what the evidence establishes

Cite material factual claims near their text using exact URLs or local/document paths and relevant sections, symbols or revisions/dates. Distinguish requirements, documented behavior, inspected code, executed reproduction/measurement, inference and recommendation. Static inspection does not establish runtime behavior. Never invent citations, measurements or successful checks.

Preserve contrary evidence. Assess conflicting sources by authority for the concern and accepted decisions, not tool ranking. Distinguish unavailable/partial evidence from evidence against a claim. State material coverage limits; no result in the inspected scope does not prove nonexistence.

Ground project/product/domain choices in exact project sources. Ask the user before dependent work or acceptance on a material unresolved choice and offer a user-chosen, authorized decision issue. Use the standalone [project decision procedure](../../agents/references/project-decisions.md) for source reconciliation and escalation; continue independent authorized research and label recommendations as proposals.

## Return only the requested artifact

Lead with findings, sources, material uncertainty and what remains unresolved. Follow the requested format/return contract. Read-only or answer-only requests create no files. For a requested note, use one concise Markdown file at the established location unless the requested format or existing documentation requires otherwise; reuse authoritative notes where appropriate. Delegated evidence gathering does not authorize editing the final integrated deliverable.

Write only within assigned artifact/location scope. Research does not authorize product/database changes, external messages, publication or access changes. Writing, modifying, deleting or running tests, including executable reproductions/evaluations, requires explicit user authorization. Use permitted inspection/non-test checks and reuse applicable authorization and deferrals without asking again. Keep credentials out of evidence.

## Delegate only when useful and permitted

Use a background **researcher** when available, permitted and independent alongside useful work; otherwise research locally. Select the [researcher profile](/Users/joostwaaijer/.codex/agents/researcher.toml) through the exposed native field. If unsupported, include its `developer_instructions` in the brief; a name/path alone does not load it. If unavailable, retain this scoped method and disclose the limitation without inventing tool arguments or launching another runtime.

Pass the exact question, source boundaries, decisions, paths/revisions/versions, expected evidence/deliverable, write ownership and permissions. Keep context minimal and avoid duplicate searches. Honor delegation/further-delegation restrictions; return findings/gaps to the coordinator without assigning the next roadmap step or starting another team. Small investigations need no full agent-team workflow.
