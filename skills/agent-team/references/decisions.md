# Project decisions in agent-team

Use the standalone [project decision procedure](../../../agents/references/project-decisions.md) for source reconciliation, material gaps and user-chosen project-manager issues. It owns that procedure for both standalone skills and team work; reading it requires no team setup or plan.

Keep the essential boundary in every assignment: ground consequential choices in exact project sources, ask the user before dependent work on a material unresolved choice, and publish a decision issue only within actual authorization. Reuse settled decisions and continue independent authorized work.

## Coordinator responsibilities

Delegated specialists return the question, source evidence and limits, practical implications and affected work to their existing coordinator. The coordinator consolidates duplicate questions and asks the user for direct input or their choice of a decision issue; do not assign a specialist to silently choose the missing outcome.

When an authorized issue is created, link its unresolved dependency from existing requirement/roadmap/run state within the assigned write scope. A tracker state is not the decision. Resume dependent work only after explicit user input or an accepted authoritative project decision; pass the resolved contract and evidence to affected owners. Record readiness and authority separately rather than treating a plan, issue or profile as permission.
